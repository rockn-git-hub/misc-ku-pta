# 2026-04-12 Vercel Blob 状況メモ

## 結論

- 現在の本番障害の直接原因は、`Vercel Blob` ストアの停止です。
- アプリ側ではなく、ストレージ側が `403 Forbidden` を返しています。
- そのため、現時点では `300人同時アクセス` の改善より先に、Blob ストアの復旧が必要です。

## 確認できた事実

- 本番 API `GET /api/public-docs` と `POST /api/session` は失敗していました。
- Vercel の実行ログでは、`manifest.json` 読み込み時に `Vercel Blob: Failed to fetch blob: 403 Forbidden` が出ていました。
- ローカルで本番の `BLOB_READ_WRITE_TOKEN` を使って検証したところ、`list()` は成功しました。
- ただし `get()` と `put()` は失敗し、本文として次の状態を確認しました。
  - `Your store is blocked`
  - `This store has been suspended.`

## 影響

- 既存資料の一覧表示
- PIN ログイン
- 資料本文の取得
- 管理画面での資料操作

上記はすべて Blob ストアに依存するため、ストア停止中は正常に動きません。

## 今回入れた対処

- API 側で Blob ストア停止を検知した場合、`500` ではなく `503` を返すように変更しました。
- メッセージは「現在、資料ストレージが停止しているため利用できません。しばらくしてから再度お試しください。」です。
- あわせて、閲覧系と管理系 API の日本語メッセージを整理しました。

## 300人同時アクセスに関する認識

- `private Blob -> Vercel Function 経由` で各ページを返す構成は、一斉アクセスに弱いです。
- そのため、今後は `PIN 認証後に public URL の画像を直接配信する構成` を優先します。
- コード側では、`api/document.js` が `page.publicUrl` を返せる形まで進めてあります。
- ただし、Blob ストアが停止中のため、本番での再確認は未実施です。

## 次にやること

1. Vercel 側で Blob ストア停止の理由を確認する
2. ストアを復旧する、または新しいストアへ切り替える
3. 画像の public 直配信で再度負荷試験を行う
4. `300人同時アクセス` の再測定を行う
